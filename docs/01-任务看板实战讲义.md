目标：从只有标题的“任务看板”菜单，做出真实数据三列看板、新建编辑抽屉、删除、筛选、复制摘要，以及可持久化的跨列拖拽。技术重点是**业务组件边界 + 第三方能力接入 + 异步状态一致性**。

阅读顺序：学习目标 → 实现步骤 → 原理说明 → 结果验证。每个阶段都提供完整代码，最终业务实现与 `apps/admin` 对应文件一致，可用于学习对照。

接口参数、返回值与 TypeScript 类型可随时查阅[配套接口文档](02-任务看板接口与TypeScript类型.md)。

## 第 0 步：了解目标功能与接口

先打开完整版 http://localhost:5666/tasks ，观察三列任务的状态流转和编辑抽屉。再进入初始版 http://localhost:5667/tasks ，从标题页开始实现相同的数据流。操作完整版时使用自己新建的练习任务。

打开以下已有文件，只读，不重写：

- `frontend/apps/starter/src/router/routes/modules/tasks.ts`：菜单已注册，业务入口就是 `views/tasks/index.vue`。
- `frontend/apps/starter/src/api/tasks.ts`：Task、TaskInput、TaskMove 与接口函数。
- `frontend/apps/starter/src/api/request.ts`：已处理鉴权、响应解包和错误提示，业务页面直接调用接口函数即可。

接口速记（实际浏览器 URL 带 `/api`，API 模块里只写 `/tasks`）：

| 调用 | 传入 | 返回 |
|---|---|---|
| `getTaskBoard()` | 无 | `{ items, version }` |
| `saveTask(data, version, id?)` | 不传 id 新建，传 id 编辑 | 最新完整看板 |
| `removeTask(id, version)` | 任务 id、看板版本 | 最新完整看板 |
| `moveTask({ id, status, beforeId }, version)` | 移到哪列、放在哪张卡前 | 最新完整看板 |

`status` 是 `todo / doing / done`；`priority` 是 `low / medium / high`；`dueDate` 是 `YYYY-MM-DD` 或空字符串。`version` 是整张看板的版本，所有写入都要传。`beforeId = 0` 表示目标列末尾。

**职责与数据流**：

页面负责安排组件，卡片负责展示，抽屉负责收集输入，组合函数负责与服务器同步。Gin 接口已提供，本练习通过真实请求验证从页面交互到数据库保存的完整链路。

请求函数返回的已经是 data，不再写 response.data.data。服务器每次返回完整看板，前端据此更新页面和版本。

后端模块的职责和调用关系见 [后端调用链](../backend/README.md#调用链)。

## 第 1 步：先让真实数据出现

### 1.1 新建读取状态

创建 `composables` 目录，通过 `board` 保存看板数据，使用 `refresh()` 请求并更新状态。下面同时处理请求顺序和卸载清理。本阶段先完成数据读取，表单与拖拽在后续步骤接入。

**文件：`frontend/apps/starter/src/composables/use-task-board.ts`**

操作：整文件写入（已有文件就整文件替换）。以下为本步完整代码，不含省略号。

<!-- lesson stage=T1 path=composables/use-task-board.ts mode=file -->
```ts
import type { TaskBoard } from '../api/tasks';
import { onScopeDispose, ref } from 'vue';
import { getTaskBoard } from '../api/tasks';

export function useTaskBoard() {
  const board = ref<TaskBoard>({ items: [], version: 0 });
  const loading = ref(false);
  const failed = ref(false);
  let requestId = 0;
  async function refresh() {
    const current = ++requestId;
    loading.value = true;
    try {
      const result = await getTaskBoard();
      if (current !== requestId) return;
      board.value = result;
      failed.value = false;
    } catch {
      if (current === requestId) failed.value = true;
    } finally {
      if (current === requestId) loading.value = false;
    }
  }
  onScopeDispose(() => { requestId++; });
  return { board, loading, failed, refresh };
}
```

### 原理与结果验证

先把“能取数据”与“排版好看”分开。组合函数只管理请求状态，页面在 onMounted 调它；拿到数据后改变 ref，Vue 更新模板。

requestId 让最后发出的请求拥有更新页面的资格。它不是取消 HTTP 请求，而是忽略过期响应；卸载时也让未结束的请求失效。

验收：看到真实任务标题与版本数字；Network 中 `GET /api/tasks` 成功；点击刷新能再次请求。只读接口不需要改数据库。若出现 401，先检查登录是否过期并重新登录。此阶段 `version` 可以展示，正式页面会隐藏这种实现细节。

import type { Task, TaskPriority, TaskStatus } from '#/api/tasks';
import dayjs from 'dayjs';

export const statuses: { value: TaskStatus; label: string; hint: string }[] = [
  { value: 'todo', label: '待处理', hint: '整理想法，明确下一步' },
  { value: 'doing', label: '进行中', hint: '专注推进，及时协作' },
  { value: 'done', label: '已完成', hint: '记录成果，让进度可见' },
];
export const priorities: {
  value: TaskPriority;
  label: string;
  type: 'info' | 'warning' | 'danger';
}[] = [
  { value: 'high', label: '高优先级', type: 'danger' },
  { value: 'medium', label: '中优先级', type: 'warning' },
  { value: 'low', label: '低优先级', type: 'info' },
];
export function isOverdue(task: Task, today = dayjs().format('YYYY-MM-DD')) {
  return task.status !== 'done' && !!task.dueDate && task.dueDate < today;
}
```

import type { Task, TaskBoard, TaskInput, TaskMove } from '../api/tasks';
import { computed, onScopeDispose, ref } from 'vue';
import { getTaskBoard, moveTask, removeTask, saveTask } from '../api/tasks';

export function applyTaskMove(items: Task[], move: TaskMove): Task[] {
  const task = items.find((item) => item.id === move.id);
  if (!task) return items;
  const next = items.filter((item) => item.id !== move.id);
  const anchor = move.beforeId
    ? next.findIndex(
        (item) => item.id === move.beforeId && item.status === move.status,
      )
    : next.length;
  if (anchor < 0) return items;
  next.splice(anchor, 0, { ...task, status: move.status });
  return next;
}

export function useTaskBoard() {
  const board = ref<TaskBoard>({ items: [], version: 0 });
  const loading = ref(false);
  const pending = ref(false);
  const failed = ref(false);
  const ready = computed(() => board.value.version > 0 && !failed.value);
  let requestId = 0;
  let disposed = false;
  async function read() {
    const current = ++requestId;
    loading.value = true;
    try {
      const result = await getTaskBoard();
      if (current !== requestId || disposed) return;
      board.value = result;
      failed.value = false;
    } catch {
      if (current === requestId && !disposed) failed.value = true;
    } finally {
      if (current === requestId && !disposed) loading.value = false;
    }
  }
  async function refresh() {
    if (!pending.value) await read();
  }
  async function mutate(
    request: () => Promise<TaskBoard>,
    optimistic?: TaskMove,
  ) {
    if (pending.value || loading.value || !ready.value || disposed)
      return false;
    pending.value = true;
    const previous = board.value;
    if (optimistic)
      board.value = {
        ...previous,
        items: applyTaskMove(previous.items, optimistic),
      };
    try {
      const result = await request();
      if (!disposed) board.value = result;
      return true;
    } catch {
      if (!disposed) {
        board.value = previous;
        // 超时可能已经写入；恢复本地快照后重读服务端，失败则锁定写入直到刷新成功。
        await read();
      }
      return false;
    } finally {
      pending.value = false;
    }
  }
  function save(data: TaskInput, id?: number) {
    return mutate(() => saveTask(data, board.value.version, id));
  }
  function remove(id: number) {
    return mutate(() => removeTask(id, board.value.version));
  }
  function move(data: TaskMove) {
    return mutate(() => moveTask(data, board.value.version), data);
  }
  onScopeDispose(() => {
    disposed = true;
    requestId++;
  });
  return {
    board,
    loading,
    pending,
    failed,
    ready,
    refresh,
    save,
    remove,
    move,
  };
}
```

**读写状态与失败恢复**：

loading 表示正在读取，pending 表示正在写入。没拿到有效版本之前不能提交。成功时采用服务器返回的整份快照，失败后先恢复旧快照，再重读服务器。

失败不一定代表服务器没保存，例如响应超时，所以不能只把本地数组放回去就结束。如果重读也失败，ready 会变成 false，必须刷新成功后才能继续写入。

## 第 4 步：拖拽不只是让卡片动起来

### 4.1 替换看板 script

找到 `views/tasks/components/task-board.vue` 顶部原 `<script setup lang="ts">` 到 `</script>`，**只替换这一整段**；保留第 2 步的 template 和 style。不安装新包，使用项目已有 `@vben/hooks` 的 `useSortable`。初始化方法需要 await，实例要在卸载时 destroy。

**文件：`frontend/apps/starter/src/views/tasks/components/task-board.vue`**

操作：只替换原来的整个 `<script setup lang="ts">…</script>`，template 和 style 保留。以下为本步完整代码，不含省略号。

<!-- lesson stage=T4 path=views/tasks/components/task-board.vue mode=script -->
```vue
<script setup lang="ts">
import type { Task, TaskMove, TaskStatus } from '#/api/tasks';
import type { Sortable } from '@vben/hooks';
import { nextTick, onBeforeUnmount, onMounted, ref, watch } from 'vue';
import { useSortable } from '@vben/hooks';
import { ElButton, ElMessage } from 'element-plus';
import { statuses } from '../task-meta';
import TaskCard from './task-card.vue';

const props = defineProps<{
  items: Task[];
  disabled: boolean;
  dragDisabled: boolean;
}>();
const emit = defineEmits<{
  move: [TaskMove];
  edit: [Task];
  remove: [Task];
  copy: [Task];
  add: [TaskStatus];
  dragging: [boolean];
}>();
const columns = ref<HTMLElement[]>([]);
const sortables: Sortable[] = [];
let disposed = false;
watch(
  () => props.disabled || props.dragDisabled,
  (disabled) => {
    sortables.forEach((sortable) => sortable.option('disabled', disabled));
  },
);
onMounted(async () => {
  await nextTick();
  try {
    for (const container of columns.value) {
      const { initializeSortable } = useSortable(container, {
        group: 'lesson-task-board',
        handle: '.drag-handle',
        draggable: '.task-card',
        animation: 180,
        ghostClass: 'task-ghost',
        chosenClass: 'task-chosen',
        disabled: props.disabled || props.dragDisabled,
        onStart: () => emit('dragging', true),
        onEnd(event) {
          const { item, from, to, oldDraggableIndex, newDraggableIndex } =
            event;
          const status = to.dataset.status as TaskStatus;
          const beforeId = Number(
            (item.nextElementSibling as HTMLElement | null)?.dataset.id || 0,
          );
          const id = Number(item.dataset.id);
          // Sortable 已移动真实 DOM；先还原，再让 Vue 根据响应式数据完成渲染。
          item.remove();
          from.insertBefore(
            item,
            from.querySelectorAll(':scope > .task-card')[
              oldDraggableIndex ?? 0
            ] ?? null,
          );
          emit('dragging', false);
          if (from === to && oldDraggableIndex === newDraggableIndex) return;
          emit('move', { id, status, beforeId });
        },
      });
      const sortable = await initializeSortable();
      if (disposed) {
        sortable.destroy();
        return;
      }
      sortable.option('disabled', props.disabled || props.dragDisabled);
      sortables.push(sortable);
    }
  } catch {
    ElMessage.error('拖拽初始化失败，可通过编辑修改任务状态');
  }
});
onBeforeUnmount(() => {
  disposed = true;
  sortables.forEach((sortable) => sortable.destroy());
});
</script>
```

操作完成后，手动刷新一次页面，确保从静态组件升级到拖拽组件时实例完整初始化。

### 4.2 理解拖拽数据流

1. `group` 让三个容器互通，`handle` 只允许按手柄拖，`draggable` 指定真正的卡片。
2. 松手时，Sortable 已移动真实 DOM。先读目标列 `to.dataset.status`、卡片 id，以及它下一个兄弟卡片的 id。
3. `beforeId` 表达“放在谁前面”，末尾为 0，不把前端数组下标当数据库位置。空列的提示不在 `.column-list` 内，避免误判为锚点。
4. 先 `item.remove()`，再按 `oldDraggableIndex` 把 DOM 放回源列；随后 emit 数据事件，让 Vue 根据响应式数组渲染新位置。
5. 页面 `moveCard → move → mutate`：保存旧快照，先用 `applyTaskMove` 改本地数组，再请求 PATCH；成功采用服务器快照，失败恢复并重读。

如果不恢复 DOM，Sortable 与 Vue 都在操作同一份节点顺序，可能出现重复、错位或回弹。拖拽库负责识别动作，Vue 负责最终渲染。

回到已有的 `composables/use-task-board.ts`，对照以下逻辑理解一次移动如何保存：

- `applyTaskMove` 先移出当前任务，再寻找目标列锚点，创建新对象和新数组，不破坏旧快照。
- `mutate` 中 `previous` 是恢复依据，`optimistic` 是“先更新 UI”的开关。
- `moveTask(data, board.value.version)` 带当前全局版本；服务端发现版本过期返回 409，前端重读。
- `pending` 期间禁用继续操作，避免上一次保存未结束又发起下一次排序。

示例：todo `[A, B]`，doing `[C]`；把 B 放在 C 前，发送 `{ id: B.id, status: 'doing', beforeId: C.id }`，服务端返回 todo `[A]`、doing `[B, C]` 和新 version。将 B 放到 done 空列则 `beforeId: 0`。

### 4.3 验收

先新建两条带 `CLASS-` 前缀的任务用于操作。

| 动作 | 应看到什么 |
|---|---|
| 跨列拖入进行中 | 卡片立即移动；Network 有 PATCH `/api/tasks/:id/move`，带 version/status/beforeId |
| 在同列交换两张练习卡片 | 顺序改变；刷新后顺序不丢 |
| 拖入空列或列末尾 | beforeId 为 0；保存后位置正确 |
| 输入筛选条件 | 手柄禁用，清空筛选恢复 |

存在空列时，可将自己创建的任务拖入空列，验证 `beforeId = 0` 的行为；也可以拖到已有列的末尾验证追加。空列场景应在独立练习数据中测试，保留其他人的任务。

## 第 5 步：筛选、组件复用与异常验证

### 5.1 理解筛选与统计

打开第 3 步已写入的 `views/tasks/index.vue`，查看三个计算逻辑：

- `visibleTasks`：在完整 `board.items` 上用 computed 做关键词、负责人/编号、优先级和逾期筛选，不发额外 GET。
- `filtering`：任何条件生效就禁用拖拽。当前看到的是局部列表，隐藏的卡片可能改变排序语义；编辑抽屉仍可修改状态。
- `completed / doing / overdue / completion`：统计整张看板，不随筛选结果偷偷变成局部统计。空看板完成率为 0，避免除零。

这个接口返回完整看板，最多 200 条，所以本地筛选成立。如果变成分页接口，不能只过滤当前页再声称搜遍所有任务，必须重新设计服务端查询与排序。

依次输入负责人、选择高优先级、打开“仅看逾期”，再点击重置；`priority` 清空后应回到 `''`。逾期结果取决于当前日期，可新建一条截止昨日且未完成的练习任务进行验证。

### 5.3 网络故障与版本冲突

以下两个实验分别验证网络失败与并发冲突。分别完成这两个实验，并观察 Network 请求和页面状态。

- **断网**：开发者工具切 Offline，拖动一张练习任务。应先乐观移动，再恢复；重读失败出现提示并禁用写入。切回 Online，点击刷新恢复操作。不要关闭 Go 进程，重启会让登录失效。
- **版本冲突**：A、B 两个标签页先刷新，A 修改一条练习任务；B 不刷新再拖动。B 写入带旧 version，收到 409，然后刷新为服务端最新状态。没有实时推送；用户确认新状态后再操作，代码不会默默重放旧意图。抽屉保存失败时仍保留草稿。
