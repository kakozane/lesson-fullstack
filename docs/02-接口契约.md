# 商品管理 API 契约

实现：Gin + GORM；本次分层改造保持已有接口契约，URL、字段名称、HTTP 错误码和成功码 0 均不变。

开发地址：`http://127.0.0.1:8080/api`。浏览器使用同源 `/api`，由 Vite 代理。请求 JSON，响应 UTF-8 JSON。

除健康检查和登录外，均需要 `Authorization: Bearer <accessToken>`。

任务模块 `/tasks` 的独立 DTO、移动接口和看板版本约定见 `07-任务接口与验收.md`，商品接口保持不变。

## 统一响应

```json
{"code":0,"data":{},"message":""}
```

失败使用对应 HTTP 状态码，code 与 HTTP 状态一致，data 为 null，message 是可展示给用户的错误信息。

| HTTP | 含义 |
|---|---|
| 400 | 请求格式、分页或字段校验失败 |
| 401 | 未登录、凭证过期、账号密码错误 |
| 404 | 商品不存在或已被删除 |
| 409 | 编码重复，或批量操作包含已删除商品 |
| 500 / 503 | 服务或数据库暂时不可用 |

Vben `requestClient` 已解包 data，页面收到的是 ProductPage，而不是 axios response。

## 登录与框架支持

| 方法与路径 | 参数 / 返回 |
|---|---|
| GET /health | 无需登录，返回 `{status:"ok"}`，检查数据库连接 |
| POST /auth/login | `{username:"admin",password:"..."}`，返回 `{accessToken:"..."}` |
| GET /user/info | 返回 username、realName、roles、homePath、avatar 等 |
| GET /auth/codes | 返回权限码数组 |
| POST /auth/logout | 使当前 token 失效 |
| GET /categories | 返回 `["数码配件","办公文具","生活好物"]` |

会话保存在 Go 内存中，有效期 8 小时；服务重启后须重新登录。不提供 refresh 接口，前端关闭自动刷新 token。菜单为前端路由模式，不调用菜单接口。

## 商品字段

| 字段 | 类型 | 约束 |
|---|---|---|
| id | integer | 服务端生成，查询返回 |
| name | string | trim 后 1～80 个字符 |
| sku | string | 1～32 位 ASCII 字母、数字、短横线；唯一，默认数据库排序规则不区分大小写 |
| category | string | 必须来自分类列表 |
| priceCents | integer | 1～99999999 分，即 0.01～999999.99 元 |
| stock | integer | 0～999999 |
| status | 0 或 1 | 0=下架，1=上架，必须提供 |
| description | string | 最多 500 个字符，可为空 |
| updatedAt | string | 查询返回，格式 YYYY-MM-DD HH:mm:ss，数据库会话使用 UTC+8 |

## 查询列表

`GET /products`

| 参数 | 默认 | 说明 |
|---|---|---|
| keyword | 空 | 名称或编码包含查询，最多 80 个字符，% 和 _ 按普通文本处理 |
| category | 空 | 精确匹配；空表示全部 |
| status | 空 | 0 / 1；空表示全部 |
| page | 1 | 1～1000000 |
| pageSize | 10 | 1～100，前端提供 10 / 20 / 50 |

组合条件使用 AND，默认 id 倒序。返回的 total 与 items 使用同一事务快照。请求页码超出结果范围时返回最后一个有效页；无结果时 page=1。

```json
{
  "code": 0,
  "data": {
    "items": [{
      "id": 36,
      "name": "阅读台灯 轻享版",
      "sku": "SP-0036",
      "category": "生活好物",
      "priceCents": 28150,
      "stock": 5,
      "status": 1,
      "description": "商品描述",
      "updatedAt": "2026-10-28 11:36:23"
    }],
    "total": 36,
    "page": 1,
    "pageSize": 10
  },
  "message": ""
}
```

## 新增与编辑

- `POST /products`：新增。
- `PUT /products/{id}`：完整更新业务字段；不传 id、updatedAt。

```json
{
  "name": "无线鼠标",
  "sku": "CLASS-001",
  "category": "数码配件",
  "priceCents": 2990,
  "stock": 25,
  "status": 0,
  "description": "课堂演示"
}
```

成功返回 `{code:0,data:null,message:"保存成功"}`。前端随后重新查询列表。编辑未改变任何字段也视为成功；重复编码返回 409。当前不提供版本冲突检测，多人编辑时最后提交生效。

## 删除

`DELETE /products/{id}`，没有请求体。成功返回 data=null；不存在返回 404。永久删除，仅在界面明确确认后提交。

## 单条 / 批量上下架

`PATCH /products/status`

```json
{"ids":[35,36],"status":0}
```

ids 必须包含 1～100 个不重复的正整数。单条操作也用长度为 1 的数组。

同一事务检查全部 ID 后更新。任意 ID 不存在，整个操作返回 409，其他商品不会部分更新。相同状态再次提交也返回成功。

注意当前 Vben RequestClient 没有 patch 快捷方法，需要：

```ts
requestClient.request('/products/status', {
  method: 'PATCH',
  data: { ids, status },
});
```

## 本地配置

配置位于 backend/.env，示例见 backend/.env.example。实际数据库密码不写入文档、不写入前端，也不进入 Git。

每次启动都会执行 CREATE DATABASE IF NOT EXISTS 和 CREATE TABLE IF NOT EXISTS，已有库表不会被重建。随后检查 lesson_migrations 的版本记录，只有首次登记版本 1 时才插入 36 条种子数据，已有商品不会因重启被覆盖。不要删除该记录来刷新数据，否则可能与已有编码冲突。课前需要全新演示库时，在 .env 中换成一个新的、只含小写字母数字下划线的 DB_NAME，然后重启；不要清理已有业务库。
