## 第 0 步：了解商品管理流程与接口

打开完整版 http://localhost:5666/products ，观察筛选、编辑弹窗与批量操作。再回到初始版 http://localhost:5667/products ，从标题页开始实现商品业务。登录、菜单和布局复用现有框架。

只读这三个已有文件：

- `frontend/apps/starter/src/router/routes/modules/products.ts`：路由已指向 `views/products/index.vue`。
- `frontend/apps/starter/src/api/products.ts`：接口和类型已给定。
- `frontend/apps/starter/src/api/request.ts`：统一鉴权、错误提示与 data 解包，不重复封装 Axios。

| 接口函数 | 作用 | 注意 |
|---|---|---|
| `getProducts(query)` | GET 商品分页 | 返回 items、total、page、pageSize |
| `getCategories()` | GET 分类 | 前端选项来自接口 |
| `createProduct(data)` | POST 新建 | 编码唯一 |
| `updateProduct(id, data)` | PUT 编辑 | 提交明确字段 |
| `deleteProduct(id)` | DELETE 删除 | 成功后重读列表 |
| `batchStatus(ids, status)` | PATCH 上下架 | 单条也可以传一个 id |

**三个关键字段约定**：`priceCents` 是整数分；`status: 0` 是下架、`1` 是上架；查询 `status: ''` 是全部。库存 0 是正常值，不能把 `0` 当成“没填”。

页面展示价格用元，后端保存用分。筛选条件也是契约的一部分：空字符串表示不筛选，数字零表示只看下架，这两个意思不能混在一起。

分类以接口实际返回为准；当前课程是数码配件、办公文具、生活好物。接口响应在请求层解包后，直接用 result.items，不写 result.data.items。

## 第 1 步：查询条件、列表和分页

### 1.1 新建列表组合函数

创建 `composables` 目录，将查询与分页状态集中到 `useProductList`。重点关注 `search`、`reset`、`changePage` 如何更新查询，以及 `load` 如何处理读取和响应顺序。

**文件：`frontend/apps/starter/src/composables/use-product-list.ts`**

操作：整文件写入（已有文件就整文件替换）。以下为本步完整代码，不含省略号。

<!-- lesson stage=P1 path=composables/use-product-list.ts mode=file -->
```ts
import { onScopeDispose, reactive, ref } from 'vue';
import type { Product, ProductQuery } from '../api/products';
import { getProducts } from '../api/products';

export function useProductList() {
  const filters = reactive<
    Pick<ProductQuery, 'category' | 'keyword' | 'status'>
  >({ keyword: '', category: '', status: '' });
  const query = reactive<ProductQuery>({ ...filters, page: 1, pageSize: 10 });
  const items = ref<Product[]>([]);
  const total = ref(0);
  const loading = ref(false);
  const failed = ref(false);
  let requestId = 0;

  async function load() {
    const current = ++requestId;
    loading.value = true;
    failed.value = false;
    items.value = [];
    try {
      const result = await getProducts({ ...query });
      // 只让最新发出的请求更新页面，避免慢响应覆盖新筛选结果。
      if (current !== requestId) return;
      items.value = result.items;
      total.value = result.total;
      query.page = result.page;
    } catch {
      if (current === requestId) {
        failed.value = true;
        total.value = 0;
      }
      // 请求层统一展示错误，页面保留重试入口。
    } finally {
      if (current === requestId) loading.value = false;
    }
  }
  function search() {
    Object.assign(query, filters, { keyword: filters.keyword.trim(), page: 1 });
    return load();
  }
  function reset() {
    Object.assign(filters, { keyword: '', category: '', status: '' });
    return search();
  }
  function changePage(page: number) {
    query.page = page;
    return load();
  }
  function changeSize(pageSize: number) {
    Object.assign(query, { pageSize, page: 1 });
    return load();
  }
  onScopeDispose(() => {
    requestId++;
  });
  return {
    filters,
    query,
    items,
    total,
    loading,
    failed,
    load,
    search,
    reset,
    changePage,
    changeSize,
  };
}
```

### 理解 filters 与 query

filters 是输入框当前的内容，query 是真正发给接口的查询。输入关键词后还没点查询，翻页仍使用上次已经提交的条件，避免用户以为“翻页偷偷帮我搜索了”。分类、状态 change 和关键词 clear 在模板里主动调用 search，所以这些操作立即查询。

换筛选必须回到第一页；换每页条数也回到第一页。请求返回的 page 是服务端确认过的有效页码，删除末页数据后，前端也采用它。

`load` 开始时清空 items，后面加入多选时，旧页的选择不会悄悄留到新结果。请求序号只接纳最新查询，旧请求回来也不能提前关掉新请求的 loading。失败时清空总数并显示重试入口，不伪装成成功空列表。

### 结果验证与思考

1. 翻到第二页，再选“下架”，Network 查询参数中 `status=0`，page 回到 1。
2. 清空状态，应该查全部；输入关键词点查询，再清空关键词或点击重置，列表恢复。
3. 切每页 20 条，page 回到 1；总数是服务端 total，不是当前 items.length。
4. 输入无匹配关键词看到空态；不要把请求失败提示当作空态。

**思考：如果写成 `status || ''` 会怎样？** 下架值 0 会被转换为空字符串，查询条件因此变成“全部”。此外，`:value="0"` 传入数字，而 `value="0"` 传入字符串，参数类型也需要与接口一致。

## 第 2 步：新增和编辑共用一个业务表单

### 2.1 新建 ProductForm

下面的组件包含模板、校验规则和离开保护。阅读时沿着 `watch` 初始化草稿 → `submit` 转换字段 → create/update 保存的顺序，理解新增与编辑如何复用同一套表单。

**文件：`frontend/apps/starter/src/views/products/product-form.vue`**

操作：整文件写入（已有文件就整文件替换）。以下为本步完整代码，不含省略号。

<!-- lesson stage=P2 path=views/products/product-form.vue mode=file -->
```vue
<script setup lang="ts">
import type { FormInstance, FormRules } from 'element-plus';
import type { Product, ProductInput } from '#/api/products';
import { computed, nextTick, onBeforeUnmount, reactive, ref, watch } from 'vue';
import { onBeforeRouteLeave } from 'vue-router';
import {
  ElButton,
  ElDialog,
  ElForm,
  ElFormItem,
  ElInput,
  ElInputNumber,
  ElMessage,
  ElMessageBox,
  ElOption,
  ElSelect,
  ElSwitch,
} from 'element-plus';
import { createProduct, updateProduct } from '#/api/products';

const props = defineProps<{
  modelValue: boolean;
  product?: Product;
  categories: string[];
}>();
const emit = defineEmits<{ 'update:modelValue': [boolean]; saved: [] }>();
const formRef = ref<FormInstance>();
const saving = ref(false);
const form = reactive({
  name: '',
  sku: '',
  category: '',
  price: 0.01,
  stock: 0,
  status: 0 as 0 | 1,
  description: '',
});
let initial = '';
const dirty = computed(
  () => props.modelValue && JSON.stringify(form) !== initial,
);
const rules: FormRules = {
  name: [
    {
      required: true,
      whitespace: true,
      message: '请输入商品名称',
      trigger: 'blur',
    },
    { max: 80, message: '最多 80 个字符', trigger: 'blur' },
  ],
  sku: [
    {
      required: true,
      pattern: /^[\dA-Za-z-]{1,32}$/,
      message: '请输入 1～32 位字母、数字或短横线',
      trigger: 'blur',
    },
  ],
  category: [{ required: true, message: '请选择分类', trigger: 'change' }],
  price: [
    {
      required: true,
      type: 'number',
      min: 0.01,
      max: 999999.99,
      message: '价格范围为 0.01～999999.99 元',
      trigger: 'change',
    },
  ],
  stock: [
    {
      required: true,
      type: 'integer',
      min: 0,
      max: 999999,
      message: '库存需为 0～999999 的整数',
      trigger: 'change',
    },
  ],
};
watch(
  () => props.modelValue,
  async (open) => {
    if (!open) return;
    const p = props.product;
    Object.assign(
      form,
      p
        ? {
            name: p.name,
            sku: p.sku,
            category: p.category,
            price: p.priceCents / 100,
            stock: p.stock,
            status: p.status,
            description: p.description,
          }
        : {
            name: '',
            sku: '',
            category: '',
            price: 0.01,
            stock: 0,
            status: 0,
            description: '',
          },
    );
    initial = JSON.stringify(form);
    await nextTick();
    formRef.value?.clearValidate();
  },
);
async function canLeave() {
  if (saving.value) {
    ElMessage.warning('正在保存，请稍候');
    return false;
  }
  if (!dirty.value) return true;
  try {
    await ElMessageBox.confirm('尚有未保存的修改，确定放弃吗？', '放弃修改', {
      type: 'warning',
      confirmButtonText: '放弃修改',
      cancelButtonText: '继续编辑',
    });
    return true;
  } catch {
    return false;
  }
}
async function close() {
  if (await canLeave()) emit('update:modelValue', false);
}
onBeforeRouteLeave(canLeave);
function beforeUnload(event: BeforeUnloadEvent) {
  if (dirty.value || saving.value) {
    event.preventDefault();
    event.returnValue = '';
  }
}
window.addEventListener('beforeunload', beforeUnload);
onBeforeUnmount(() => window.removeEventListener('beforeunload', beforeUnload));
async function submit() {
  if (saving.value) return;
  saving.value = true;
  try {
    if (!(await formRef.value?.validate().catch(() => false))) return;
    const data: ProductInput = {
      name: form.name.trim(),
      sku: form.sku.trim(),
      category: form.category,
      priceCents: Math.round(form.price * 100),
      stock: form.stock,
      status: form.status,
      description: form.description.trim(),
    };
    if (props.product) await updateProduct(props.product.id, data);
    else await createProduct(data);
    ElMessage.success(props.product ? '商品已更新' : '商品已创建');
    emit('update:modelValue', false);
    emit('saved');
  } catch {
    // 保存失败时保留输入，由请求层显示错误信息。
  } finally {
    saving.value = false;
  }
}
</script>

<template>
  <ElDialog
    :model-value="modelValue"
    :title="product ? '编辑商品' : '新增商品'"
    width="600px"
    class="product-dialog"
    :before-close="close"
    :close-on-click-modal="false"
    :close-on-press-escape="!saving"
    :show-close="!saving"
    destroy-on-close
  >
    <ElForm
      ref="formRef"
      :model="form"
      :rules="rules"
      label-width="90px"
      :disabled="saving"
      @submit.prevent="submit"
    >
      <ElFormItem label="商品名称" prop="name"
        ><ElInput
          v-model="form.name"
          maxlength="80"
          show-word-limit
          placeholder="例如：无线蓝牙鼠标"
      /></ElFormItem>
      <ElFormItem label="商品编码" prop="sku"
        ><ElInput
          v-model="form.sku"
          maxlength="32"
          placeholder="例如：SP-0037，编码不可重复"
      /></ElFormItem>
      <ElFormItem label="商品分类" prop="category"
        ><ElSelect
          v-model="form.category"
          placeholder="请选择分类"
          class="w-full"
          ><ElOption
            v-for="item in categories"
            :key="item"
            :label="item"
            :value="item" /></ElSelect
      ></ElFormItem>
      <ElFormItem label="销售价格" prop="price"
        ><ElInputNumber
          v-model="form.price"
          :min="0.01"
          :max="999999.99"
          :precision="2"
          :step="1"
          controls-position="right"
          aria-label="销售价格"
        /><span class="text-muted-foreground ml-3">元</span></ElFormItem
      >
      <ElFormItem label="商品库存" prop="stock"
        ><ElInputNumber
          v-model="form.stock"
          :min="0"
          :max="999999"
          :precision="0"
```

### 理解表单的数据流与校验

1. `product` 有值就是编辑，没有值就是新增；每次打开都重新填充草稿并清除旧校验。
2. `form` 与列表对象分开。编辑取消不修改列表，关闭后再点新增，也不会残留上一次编辑的字段。
3. 回填 `priceCents / 100`，提交 `Math.round(form.price * 100)`；`toFixed(2)` 用于显示，它返回字符串，不用于给整数分字段赋值。
4. ElSwitch 的 active/inactive 值明确为 1/0；库存 0、下架 0、空描述都应提交，不能用真假判断过滤这些字段。
5. 先校验再请求；saving 在校验前加锁，finally 解锁。成功关闭并 emit saved；错误交给请求层提示，表单输入保留。

ProductForm 已经是业务组件了：它知道商品有哪些字段、金额怎么转换、如何选择新建或编辑。ElDialog 只是提供弹窗行为，ElForm 只是提供校验和布局。这些商品字段与规则构成了 ProductForm 的业务职责。

`dirty` 比较只包含可编辑标量字段的草稿快照，适合本课的小表单；若换成富文本、文件列表或复杂对象，应重新设计脏数据判断。日期、上传、富文本都不是本课必需。

### 本阶段验收

创建一条本次独有编码，例如 `CLASS-P-1028-01`；若已存在就换后缀，不删除原记录。

| 输入或操作 | 预期 |
|---|---|
| 商品名空白、编码含空格 | 校验不通过，不请求保存 |
| 售价 19.90、库存 0、下架 | Network 提交 priceCents=1990、stock=0、status=0 |
| 编辑刚创建的记录 | 价格回填 19.90，字段无串值 |
| 清空描述并保存 | 刷新后描述仍为空 |
| 改标题后取消、选择继续编辑 | 草稿保留；确认放弃后列表不变 |
| 删除点取消，再确认删除练习记录 | 取消不删除，确认后列表重读 |

新商品可能不符合当前筛选条件，因此保存后未出现在当前列表不一定是失败。可先重置筛选，或按新编码搜索，检查实际保存结果。

```vue
          layout="total, sizes, prev, pager, next"
          @size-change="changeSize"
          @current-change="changePage"
        />
      </div>
    </ElCard>
    <ProductForm
      v-model="dialogVisible"
      :product="editing"
      :categories="categories"
      @saved="saved"
    />
  </div>
```

### 3.2 理解批量写入流程

`changeStatus` 按以下顺序执行：

1. 先挡掉 operating/loading；没选中 id 就直接返回。
2. 在确认框打开前就抓取本次 ids，并置 operating 为 true，避免连续弹窗或选择变化影响已确认的对象。
3. 用户确认后调用一次 `batchStatus(ids, status)`，不在浏览器循环调用 N 次单条接口。
4. 成功提示 → 清空选择 → 重读服务端列表；即使当前筛选是“上架中”，批量下架后这些行自然消失。
5. 取消和请求失败都走 finally 解锁；错误由请求层提示，取消无需报警。

单条和批量操作的业务都是“把这些 id 改成某个状态”。共用函数的依据是业务一致，不是为了少写一个函数。我们也明确告诉用户只选当前页，没有实现跨页全选。

`row-key="id"` 提供稳定行标识，但跨页保留选择需要额外设计。这里没有启用 reserve-selection，加载新结果清空原 items，也会让表格清掉旧选择。

### 3.3 验收

提前用弹窗新建两件 `CLASS-P-*` 练习商品，按这个前缀筛选后只选择它们。

- 单条上下架与批量上下架都成功，Network 中一次 PATCH 带 ids 数组和数字 status。
- 没选记录时批量按钮禁用；确认弹窗取消不请求。
- 操作成功后已选数量变为 0；翻页或重置后，旧页选择不会被带进下一次操作。
- 操作期间有提示，重复点击不能发两组写请求。

## 第 4 步：组件复用与边界验证

### 4.1 业务组件与三方组件的协作

| 能力层 | 使用的组件 | 职责 |
|---|---|---|
| 项目业务样式入口 | @vben/common PageHeader、Vben 主题类 | 沿用后台一致风格 |
| 通用表格与查询控件 | ElTable、ElPagination、ElInput、ElSelect | 通过 props 和事件与状态连接 |
| 通用输入与校验 | ElForm、ElInputNumber、ElSwitch、ElDialog | 字段类型、校验、受控显示 |

| 商品业务组件 | ProductForm | 封装商品字段与金额转换，兼容新增编辑 |

框架已经提供的能力直接用，第三方组件不替你决定业务。服务端分页、当前页选择范围、金额用分、提交后重新读取，这些仍由我们设计。

### 4.2 边界验证

| 场景 | 操作 | 预期 |
|---|---|---|
| 下架与全部 | 选下架，再点清空 | status=0 被保留；清空回全部 |
| 查询生效时机 | 输入新关键词不提交，翻页 | 仍使用已提交 query；回车才搜索新词 |
| 零值保存 | 编辑练习商品为库存 0、下架、空描述 | 重开和刷新值都正确 |
| SKU 冲突 | 尝试新建相同编码 | 后端拒绝；弹窗与输入保留；不关窗伪装成功 |
| 末页删除 | 按独有练习编码筛选，仅剩一件后删除 | 列表 total=0、page 采用服务端有效页；不永久停留无效页 |
| 请求失败 | 开发者工具 Offline，点击刷新，再恢复网络并重试 | 显示错误可重试，loading 最终结束 |
| 连续查询 | 网络调慢后快速改两个条件 | 旧响应不覆盖新条件结果 |

删除唯一一件匹配商品只能验证空结果页。要验证多页末页回退，可在独立练习环境新建 11 件同一前缀的商品，按前缀筛选、每页显示 10 件，然后删除第 2 页的那件商品；预期列表回到第 1 页，总数变为 10。只操作自己创建的记录。

注意区分取消操作、服务端拒绝和网络失败：取消不需要红色报错；服务端校验显示原因；网络失败保留可重试入口。保存失败后不得自动清空用户输入。

商品模块没有任务看板的版本锁，多个标签同时编辑同一商品是最后一次成功提交覆盖前面的结果；loading 只能限制当前页面的重复操作，无法解决跨用户编辑冲突。并发冲突检测是拓展方向。

## 思考与拓展练习

### 常见问题

- **为何不在页面直接写所有逻辑？** 查询分页可以独立验证，表单可同时用于新增编辑；这些是当前已有复用与测试需求，不是预先做大而全抽象。
- **为何不用 watch 一切变化自动请求？** 查询、清空、分类改变、翻页的触发时机是明确的业务行为，用事件表达更直观，避免初始化或回填触发多余请求。
- **为何保存后不直接改这一行？** 排序、筛选、总数、有效页码由后端决定，重读结果更可靠。
- **为什么金额不直接传元小数？** 本项目契约用整数分，前端输入输出要转换；显示用两位小数，传输用整数。

拓展练习：给商品表单增加一个真正需要的业务字段并对齐 Go DTO；或者为库存不足增加页面筛选（先判断应由服务端还是前端处理）；或阅读 `frontend/apps/admin/src/composables/use-product-list.test.ts`，解释旧响应为什么不能更新页面。

## 常见问题排查

| 现象 | 先检查 |
|---|---|
| 页面没变化 | 是否编辑 starter，而浏览器误看了 5666 |
| 查询下架查成全部 | status 是否用数字 0，是否被 `\|\|` 或真假判断丢掉 |
| 保存后新商品不见 | 当前筛选是否排除了它；按新编码搜索确认 |
| 编辑后新增仍有旧数据 | watch 打开时是否覆盖完整草稿，openForm() 是否清掉 editing |
| 商品价格差 100 倍 | 回填除 100，提交乘 100，字段是否写成 priceCents |
| 批量操作选中旧数据 | selection-change、load 清空 items、saved 清空 selected 是否齐全 |
| 导入报错 | 按“组合函数 → 表单 → 页面”顺序创建，文件路径是否属于 starter/src |

最终只新增 `composables/use-product-list.ts`、`views/products/product-form.vue`，并逐步替换 `views/products/index.vue`。API、菜单、登录、共享包和 Gin 后端使用项目已有实现。
