初始版已经提供筛选区、工具栏、空表格、分页、表单弹窗和商品校验规则 rules。本练习保留现有布局、class 和 style，只补充状态、请求、字段绑定与事件。

所有文件路径相对于项目根目录。练习修改 `frontend/apps/starter/src`，完整参考实现在 `frontend/apps/admin/src`。不修改共享组件和后端接口，不复制 admin 的整个页面覆盖初始版。

后端配套阅读：[Go 后端与全栈数据流](08-Go后端与全栈数据流.md)。可沿新增商品请求理解路由、校验、数据库写入与响应，再接入前端交互。

| 约定 | 使用方式 |
|---|---|
| 分类 | 接口返回 `{ id, name }[]`，显示 name，保存数字 categoryId |
| 全部分类 | 筛选状态为 undefined，请求省略 categoryId；不添加“全部分类”选项 |
| 商品展示 | 列表返回 categoryName，表单回填 categoryId |
| 金额 | 接口用整数分，表单展示元；回填除以 100，提交乘以 100 并取整 |
| 上下架 | 1 上架、0 下架；0 是有效值，不能用真假判断过滤掉 |
| 响应 | requestClient 已解包 data；直接使用 result.items |
| 错误 | JSON code：200 成功、401 认证失败、400 其他失败；请求层统一提示 message |

## 第 1 步：封装列表查询状态

**新增文件：`frontend/apps/starter/src/composables/use-product-list.ts`。** 写入以下代码：

```ts
import type { Product, ProductQuery } from '../api/products';

import { reactive, ref } from 'vue';

import { getProducts } from '../api/products';

export function useProductList() {
  const filters = reactive<Pick<ProductQuery, 'categoryId' | 'keyword' | 'status'>>({
    keyword: '',
    categoryId: undefined,
    status: '',
  });
  const query = reactive<ProductQuery>({ ...filters, page: 1, pageSize: 10 });
  const items = ref<Product[]>([]);
  const total = ref(0);
  const loading = ref(false);
  const failed = ref(false);
  let requestId = 0;

  async function load() {
    const current = ++requestId;
    loading.value = true;
    failed.value = false;
    items.value = [];
    try {
      const { categoryId, ...params } = query;
      const result = await getProducts({
        ...params,
        ...(categoryId === undefined ? {} : { categoryId }),
      });
      // 只让最新发出的请求更新页面，避免慢响应覆盖新筛选结果。
      if (current !== requestId) return;
      items.value = result.items;
      total.value = result.total;
      query.page = result.page;
    } catch {
      if (current === requestId) {
        failed.value = true;
        total.value = 0;
      }
      // 请求层统一展示错误，页面保留重试入口。
    } finally {
      if (current === requestId) loading.value = false;
    }
  }
  function search() {
    query.keyword = filters.keyword.trim();
    query.categoryId = filters.categoryId;
    query.status = filters.status;
    query.page = 1;
    return load();
  }
  function reset() {
    filters.keyword = '';
    filters.categoryId = undefined;
    filters.status = '';
    return search();
  }
  function changePage(page: number) {
    query.page = page;
    return load();
  }
  function changeSize(pageSize: number) {
    query.pageSize = pageSize;
    query.page = 1;
    return load();
  }
  return {
    filters,
    query,
    items,
    total,
    loading,
    failed,
    load,
    search,
    reset,
    changePage,
    changeSize,
  };
}
```

理解三个行为：

- `filters` 是输入框当前值，`query` 是已提交的条件；点击查询才将关键词复制进去，翻页沿用已提交条件。
- 搜索和修改每页数量时重置为第一页。分类清空后使用 undefined，构造请求时真正移除 categoryId 属性。
- 请求序号阻止旧响应覆盖新结果；请求失败保留重试入口。逐项修改 reactive 对象的属性仍具有响应性，无需批量合并对象。

### 3.2 为表单加入草稿、校验与提交

**文件：`frontend/apps/starter/src/views/products/product-form.vue`。**

初始版已提供 `FormRules` 类型导入、完整 `rules` 常量及 ElForm 的 `:rules="rules"`，无需重新输入规则。保留这些内容，补充下面示例中的其余导入、状态和函数；同名导入需要合并，不能重复声明 rules。以下完整 script 仅供核对，也可整体替换 script 内容，已有 template 保留。

```ts
import type { FormInstance, FormRules } from 'element-plus';
import type { Category, Product, ProductInput } from '#/api/products';
import { nextTick, reactive, ref, watch } from 'vue';
import {
  ElButton,
  ElDialog,
  ElForm,
  ElFormItem,
  ElInput,
  ElInputNumber,
  ElMessage,
  ElOption,
  ElSelect,
  ElSwitch,
} from 'element-plus';
import { createProduct, updateProduct } from '#/api/products';

const props = defineProps<{
  modelValue: boolean;
  product?: Product;
  categories: Category[];
}>();
const emit = defineEmits<{ 'update:modelValue': [boolean]; saved: [] }>();
const formRef = ref<FormInstance>();
const saving = ref(false);
const form = reactive({
  name: '',
  sku: '',
  categoryId: undefined as number | undefined,
  price: 0.01,
  stock: 0,
  status: 0 as 0 | 1,
  description: '',
});
const rules: FormRules = {
  name: [
    {
      required: true,
      whitespace: true,
      message: '请输入商品名称',
      trigger: 'blur',
    },
    { max: 80, message: '最多 80 个字符', trigger: 'blur' },
  ],
  sku: [
    {
      required: true,
      pattern: /^[\dA-Za-z-]{1,32}$/,
      message: '请输入 1～32 位字母、数字或短横线',
      trigger: 'blur',
    },
  ],
  categoryId: [{ type: 'number', min: 1, required: true, message: '请选择分类', trigger: 'change' }],
  price: [
    {
      required: true,
      type: 'number',
      min: 0.01,
      max: 999999.99,
      message: '价格范围为 0.01～999999.99 元',
      trigger: 'change',
    },
  ],
  stock: [
    {
      required: true,
      type: 'integer',
      min: 0,
      max: 999999,
      message: '库存需为 0～999999 的整数',
      trigger: 'change',
    },
  ],
};
watch(
  () => props.modelValue,
  async (open) => {
    if (!open) return;
    const p = props.product;
    form.name = p?.name ?? '';
    form.sku = p?.sku ?? '';
    form.categoryId = p?.categoryId;
    form.price = p ? p.priceCents / 100 : 0.01;
    form.stock = p?.stock ?? 0;
    form.status = p?.status ?? 0;
    form.description = p?.description ?? '';
    await nextTick();
    formRef.value?.clearValidate();
  },
);
function close() {
  if (saving.value) return;
  emit('update:modelValue', false);
}
async function submit() {
  if (saving.value) return;
  saving.value = true;
  try {
    if (!(await formRef.value?.validate().catch(() => false))) return;
    const data: ProductInput = {
      name: form.name.trim(),
      sku: form.sku.trim(),
      categoryId: form.categoryId ?? 0,
      priceCents: Math.round(form.price * 100),
      stock: form.stock,
      status: form.status,
      description: form.description.trim(),
    };
    if (props.product) await updateProduct(props.product.id, data);
    else await createProduct(data);
    ElMessage.success(props.product ? '商品已更新' : '商品已创建');
    emit('update:modelValue', false);
    emit('saved');
  } catch {
    // 保存失败时保留输入，由请求层显示错误信息。
  } finally {
    saving.value = false;
  }
}
```

按以下顺序理解这段逻辑：

1. props 接收开关、编辑商品与分类；emit 通知父页面关闭和刷新。
2. form 保存独立草稿，不直接修改表格行；每次打开都完整回填或清空，防止编辑后新增残留旧值。
3. rules 负责输入校验；分类必须是有效数字 ID，库存 0 合法。
4. submit 校验后只取 ProductInput 字段，金额转换为整数分，区分新增与更新。
5. 成功后关闭并触发 saved；失败保留草稿，由请求层显示错误；finally 恢复按钮状态。

`close()` 只判断是否正在保存：保存中不关闭，其余时候直接通知父页面关闭。不设置未保存提醒、表单路由守卫或浏览器关闭监听；取消、切换页面或刷新会丢弃未保存的草稿。

## 第 4 步：接入删除与单条上下架

**文件：`frontend/apps/starter/src/views/products/index.vue`。**

```ts
const operating = ref(false);
```

追加操作函数与离开保护：

```ts
async function changeStatus(status: 0 | 1, row: Product) {
  if (operating.value || loading.value) return;
  operating.value = true;
  try {
    await ElMessageBox.confirm(
      `确定${status ? '上架' : '下架'}商品「${row.name}」吗？`,
      '确认修改状态',
      { type: 'warning', confirmButtonText: '确定', cancelButtonText: '取消' },
    );
    await updateProductStatus(row.id, status);
    ElMessage.success('商品状态已更新');
    await saved();
  } catch {
    /* 用户取消或请求层已提示错误。 */
  } finally {
    operating.value = false;
  }
}
async function remove(row: Product) {
  if (operating.value || loading.value) return;
  operating.value = true;
  try {
    await ElMessageBox.confirm(
      `确定删除「${row.name}」吗？删除后无法恢复。`,
      '删除商品',
      { type: 'warning', confirmButtonText: '删除', cancelButtonText: '取消' },
    );
    await deleteProduct(row.id);
    ElMessage.success('商品已删除');
    await saved();
  } catch {
    /* 用户取消或请求层已提示错误。 */
  } finally {
    operating.value = false;
  }
}
onBeforeRouteLeave(() => {
  if (operating.value) {
    ElMessage.warning('操作处理中，请稍候');
    return false;
  }
  return true;
});
```

### 4.1 绑定行操作事件

| 位置 | 修改内容 |
|---|---|
| 行内上下架按钮 | 添加 `@click="changeStatus(row.status === 1 ? 0 : 1, row)"`，文字改为 `{{ row.status === 1 ? '下架' : '上架' }}` |
| 行内删除按钮 | 添加 `@click="remove(row)"` |

行操作将当前商品 ID 放入 URL，请求体只传 status。成功后重新查询列表，避免页面保留旧状态。

### 4.2 补充操作锁

替换已有 disabled 属性，不要在同一标签重复写属性：

| 位置 | 最终属性 |
|---|---|
| 筛选 ElForm | `:disabled="operating"` |
| 刷新列表按钮 | `:disabled="operating || loading"` |
| 新增与行内编辑按钮 | `:disabled="operating || !categories.length"` |
| 行内上下架、删除按钮 | `:disabled="operating"` |
| ElPagination | `:disabled="operating || loading"` |

确认框打开前就设置 operating，取消、失败、成功最终都会释放。操作处理中拦截路由切换，防止用户误认为请求已取消。

**验证：** 单条上架后列表刷新；将自己的练习商品下架；取消确认框时数据不变；删除后总数和有效页码更新。

4. 测试空名称、未选择分类和重复 SKU，确认提示正确、失败保留输入。
5. 完成上架、下架和删除，仅删除自己创建的练习记录。
6. 模拟请求失败，列表可重试，按钮不会永久禁用；快速切换筛选，旧响应不会覆盖新结果。

在 frontend 目录验证：

```sh
pnpm typecheck:starter
pnpm build:starter
```

## 常见问题排查

| 现象 | 检查位置 |
|---|---|
| 页面没变化 | 编辑的是 starter，浏览器应打开 6112 |
| 分类显示数字 | 列表使用 categoryName，选项 label 使用 name，value 使用 id |
| 清空后仍筛选旧分类 | value-on-clear 返回 undefined；query 更新后，请求构造省略 categoryId |
| 下架条件丢失 | status=0 是有效值，不能用真假判断决定是否传参 |
| 弹窗打不开 | 父级 v-model、openForm 和子级 modelValue 是否都接齐 |
| 必填校验不生效 | ElForm 的 model、rules、ref 与 ElFormItem 的 prop 是否一致 |
| 新增残留编辑数据 | watch 打开时是否覆盖全部草稿字段；openForm() 是否清空 editing |
| 接口与文档不一致 | Go 进程是否已重启；重启后重新登录 |
| 保存后商品不见 | 当前筛选是否排除该商品，先用唯一 SKU 查询 |

最终只新增一个列表 composable，为已有页面和表单补充逻辑与绑定。可对照 admin 的三个对应文件核对行为，页面布局和样式无需重新实现。
